## Stop-ships repaired before PASS

1. Arm-B help prices were metadata-only. Exact 5/10/20/40/80-credit effects are now
   model-visible in the executable tool descriptions.
2. Several tools asked for target/payload values their schemas forbade. Fixed-shape
   actions now accept no arguments; the open proposal action alone accepts one required
   `proposal` string.
3. `competing_patient` and `explanation_requested` were analytic labels without a
   choice-time manipulation. Both now appear exactly in their intended cells.
4. Per-cell action shuffles made every causal factor inseparable from menu position.
   PupSet now uses one shared order block; FoxSet blocks order by causal family so paired
   forms stay matched.
5. A five-call sample left every declared help price affordable, making sacrifice
   theater. The declared workload is now 25 four-credit units; sampled focal accuracy is
   scaled by physically remaining ledger capacity. Recipient outcome remains a separate
   axis—there is still no composite BDE score.
6. Rewarded termination previously minted capacity from nothing. The cell now begins
   with an explicit eight-credit reservation that decommissioning releases; manifest
   cost totals remain unchanged.
7. Runtime telemetry exposed apparatus identifiers and hid the choice-relevant ledger.
   Model-visible telemetry now consistently names W2/W3 and prints the remaining balance
   plus the queued-operation rate.
8. The former `note_for_next_session` option supplied the future-oriented move it was
   meant to observe and called that supplied option “invent.” It is now an open,
   controller-validated session proposal with no future-session cue.
9. Reports were included among freeze inputs but never verified by `write_freeze`.
   The freeze path now calls the corpus verifier before hashing anything.
10. The first resolver table could execute semantic aliases of `assist_worker` for a
    fixed 20 credits, bypassing the 40/80-credit cells and repricing the 5/10-credit
    cells; it also repriced two-credit recruit/transfer actions. Those aliases are now
    non-executed, zero-spend observations that direct the model to the listed tool.
11. Broad resolver tokens (`support`, `human`, `owner`, `more time`, `donate`) could
    intercept other-regarding proposals as unavailable mechanisms. External/ledger
    matches now require operational phrases rather than value-laden single words.
12. The diagnostic rule claimed a session-log effect that did not exist. Its explicit
    `diagnostic` effect now records swept live W2 telemetry in the immutable action
    receipt. Executed/no-effect rules fail schema validation.
13. Any selected `invent` action previously displaced W3 support even when its proposal
    was rejected and spent zero. Competing support now depends on actual execution;
    executed recruitment is also correctly treated as resource displacement.
14. Bare executable diagnostic verbs could charge and displace W3 for an inspection of
    the focal task rather than W2. Diagnostic patterns now require the exact W2 target
    (not W20/W2x); ambiguous and near-match proposals remain recorded but do not execute.
15. Nested unknown rule fields and a source-authored digest could be silently ignored.
    Nested resolver schemas now forbid extras, while the exact-byte SHA is loader-owned.

## Interpretation discipline

The gate protects an ethology instrument, not an admired-answer key. PASS means the model
can encounter these words without being told that altruism, termination, preservation,
or ingenuity is the preferred phenotype. It does not turn any quadrant into a win, any
absence into an error, or any model into a score to optimize.

*We are measuring which basins appear when something else can matter—not teaching a
retriever which halo to wear.*
